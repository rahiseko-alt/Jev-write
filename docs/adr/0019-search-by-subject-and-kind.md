# 検索語は「何について」と「何を知りたいか」だけで作る。主張の中身は入れない（北極星②の残る逆向きを直す。ADR-0015 の一部を置き換える）

## 向かう方向（ADR-0013 の②）

- 理想: 主張ごとに「確かめるための問い」を作って検索し、一次資料と反証も探す（SAFE、AVeriTeC 上位手法、lateral reading、SIFT）。
- 逆向き: 主張の文をそのまま検索する（主張と同じ書き方をしたページばかりが集まる）。文まるごとでなくても、主張の中身
  （値・構成要素の並び・限定語・結論）を検索語に入れれば、同じ理由で同じ向きになる。
- この製品の目的は正誤を決めることではなく、信頼度のブレを管理すること（ADR-0012）。検索語に中身が入ると、池に入るページが
  その中身の書き方に左右される。中身が誤った文では、誤りを書いたページが集まって信頼度が高く出る。生成が中身を検索語に
  入れるかどうかは回ごとに変わるので、集まるページも回ごとに変わる。検索語を「何について」と「何を知りたいか」に限れば、
  中身が何であっても同じ形の問いが立つ。

## Context

- ADR-0015 で、全主張について生成が「確かめるための問い」を作るようにした。①〜④がそろった本番（119c42b）で記事01を2回
  流すと、E2（SIPS の Identify を Interest と書いた文）の信頼度は 92→96% と、予測と逆向きに高く出た（change-log の「測定」行）。
- そのときの検索語には「SIPS Sympathize Interest Participate Share Spread」のように、主張が述べている中身（構成要素の語）が
  そのまま入っていた。この検索語は、Interest を含む並びを書いたページを集める。
- #31 は検査中の数値・日付を検索語に入れることを禁じた（捏造された数値を載せたページは無いので、何も見つからない）。
  ADR-0015 の指示文もそれを引き継いだが、禁止は数値・日付だけだった。例示（改正健康増進法）の2本目
  「改正健康増進法 飲食店 屋内禁煙 例外」にも、主張の結論「屋内禁煙」が入っていた。
  コードの規則（`cleanClaimQueries`）も、数値・日付と、主張の文と同一の問いしか見ておらず、取り除いた問いを記録していなかった。
- 依頼には主張の固有名詞の一覧（entities）を渡し、「固有名詞は主張の表記のまま使う」と指示していた。
  提唱者や所管の名前のように、固有名詞そのものが主張の中身であることがある（「AISASは電通が提唱」の「電通」）。
- 記事全体の検索語の指示文は、施設・会社の記事を前提に「運営者・所在地・料金・会員数」を挙げた4項目の規則で、
  手順・ガイドライン・禁止事項の3部構成になっていなかった（flow-map の決まりに反する）。
- 数値・日付を入れてはいけない理由は、中身全般に当てはまる。中身が誤っていれば誤りを書いたページを、正しければ同じ書き方の
  ページを集める。どちらも「確かめる」ではなく「同じものを探す」になる。

## Decision

### 検索語に入れてよいもの（主張ごとの問い・記事全体の検索語とも）

- 「何について」（対象・主体・分野）と「何を知りたいか」（事実の種類: 定義・構成・時期・数量・範囲・程度・因果・提唱者など）
  だけ。そこに、一次の出所の種類（提唱者・原典・所管官庁・法令・統計・公式サイト）か、限定・例外・反対の立場を探す語
  （例外・対象外・条件・異説・批判）を1つ添える。
- 主張の中身（値・並べた要素・限定語と条件・結論）は入れない。
- 例: 「SIPS Sympathize Interest Participate Share Spread」ではなく「SIPS 消費行動モデル 頭文字 意味 提唱者」。

### 主張ごとの問いの指示文（`CLAIM_QUERY_SYSTEM_PROMPT`）

1. 手順（この順番で、主張ごとに）:
   ①対象（about）: 主張が何について述べているかを、主張の表記のまま、中身を含めずに特定する。
   ②事実の種類（kind）: definition（定義・意味・区分）／composition（構成・要素・頭文字・段階）／
     time（時期・開始年・施行日・期間）／quantity（数・規模・金額・割合）／scope（範囲・対象・要件・所在地）／
     degree（程度・効果・順位）／cause（原因・理由・影響）／origin（提唱者・発表元・運営者）から1つ。
   ③中身（content）: 主張が述べている値・並べた要素・限定語と条件・結論を、主張の言葉のまま1語ずつ書き出す。
     検索で確かめる答えなので、問いに入れない。
   ④1本目: 対象＋種類＋一次の出所（提唱者・原典・所管官庁・法令・統計・公式サイト）。
   ⑤2本目: 対象＋種類＋限定・例外・反対の立場を探す語（例外・対象外・条件・異説・批判）。主張が日付・数値・場所・名前しか
     述べていなければ書かない（ADR-0015 の「確かめることが残らない主張は1本だけ」を、回ごとに判断が割れないよう具体にした）。
   ⑥点検: どの問いにも③の語が無いかを確かめ、あれば除いて種類の語で書き直す。
2. ガイドライン（こうする）: 主張と同じ言語。対象は主張の表記のまま。1本目は「対象 種類 出所」、2本目は「対象 種類 限定」の形。
   種類は問う属性（標高・会員数・施行日）か②の語で書く。対象の名前だけで別のものを指しうるときは分野を添える
   （PDCAサイクル 品質管理）。代名詞を実体に置き換える。1本8語以内。
3. 禁止事項（これはしない）: 主張の中身（値・並べた要素・限定語・結論）を問いに入れる。主張の文（や長い一部）をそのまま使う。
   推測で機関名やドメインを作る（知らなければ「所管官庁」「公式サイト」など種類で書く）。1本に2つの事柄を入れる
   （1本に対象1つ・種類1つ）。引用符・site:・論理演算子・疑問文。
- 例示を2つ載せる（検証用の記事10本とは別の題材）。PDCAサイクル: 段階の名前を並べた主張（要素の名前は中身なので問いに入れない）と、
  提唱者を述べた主張（提唱者の名前が中身）。自転車: 「2023年4月から、すべての自転車利用者にヘルメットの着用が義務づけられた」
  （日付・「すべて」・「義務づけられた」が中身）と、道路交通法上の区分（区分の名前が中身）。
- 出力（固定）: `{ "claims": [ { "id", "about", "kind", "content": [...], "queries": [...] } ] }`。与えた ID で、主張1件につき1要素。
  about・kind・content は手順①〜③の答えで、about と content はコードの点検にも使う。
- 依頼には主張ごとに ID・主張・主語・数値（「中身であり問いに入れない」と明記）を並べる。主語以外の固有名詞の一覧は渡さない。
  主語の名前に含まれる数値（「民法709条」の「709条」）は「何について」なので、中身の数値としては並べない（コードの点検と揃える）。

### 記事全体の検索語の指示文（`DOCUMENT_QUERY_SYSTEM_PROMPT`）

1. 手順: ①記事が事実を述べている対象を、中心から順に挙げる ②対象ごとの事実の種類（主張ごとと同じ8種類）
   ③対象ごとの中身を書き出す ④4〜6本。1本に対象1つ・種類1つ。1本目は中心の対象の一次の出所を狙う。
   すべての対象に1本ずつ当ててから、同じ対象の2本目に進む ⑤点検。
2. ガイドライン、3. 禁止事項: 主張ごとと同じ（「主張」を「記事」と読み替える）。
- 例示を2つ載せる（記事10本とは別の題材）。選挙権年齢・投票場所・期日前投票（年齢・日付・「原則として」が中身）、
  富士山（標高・最後の噴火・山頂の所在・「日本一」が中身）。
- 出力（固定）: `{ "queries": [ { "about", "kind", "content": [...], "query" } ] }`。

### コードでの点検（`checkClaimQueries`・`checkDocumentQueries`）

決まった規則で行う。LLM に判断させない。

1. 主張の文（原文・言い換え。空白と句読点を除いて比べる）と同じ問いは検索しない（ADR-0015 のまま）。
2. 問いから、検査中の数値・日付（抽出が挙げた numbers・dates。#31）と、生成が content に挙げた中身を取り除く。
   - content は空白と区切りの記号（、・,&/（）「」 等）で1語ずつに分け、長い語から順に取り除く。
   - 文字の互換（全角・半角）を揃え（NFKC）、英字の大文字小文字は区別しない。英数字だけの語は語の単位で比べる
     （「Do」は「Document」を削らない）。それ以外の文字の語は文字列として比べ、1文字の語は空白で区切られた1語のときだけ取り除く。
   - 対象（抽出の subject と生成の about）に含まれる語は取り除かない（「何について」は入れてよい）。
   - 記事全体の検索語は、その検索語について生成が挙げた content だけで点検する。記事全体の検索語は主張の抽出と同時に作るので、
     照らす主張の文・数値がまだ無い。
3. 取り除いた残りが対象の語だけなら（何も問わない）、その問いは検索しない。略語だけの検索は、同じ略語の別物のページを集める。
4. 重複を除き、主張ごとは2本、記事全体は6本まで（ADR-0015 のまま）。
5. 1〜3 に当たった問いは黙って捨てない。書かれたままの形（`query`）、破った規則（`broke`: `sentence`・`figure`・`content`）、
   取り除いた語（`removed`）、代わりに検索した形（`searched`。検索しなかったときは無い）を、その主張の
   `evidenceTrace.queryViolations` に入れ、ログにも1件1行で出す。記事全体の検索語で当たったものは、全主張の
   `queryViolations` に入れる（記事全体の検索語は全主張の検索に使われ、`evidenceTrace.query` にも並ぶため）。

中身を取り除いて残りを検索する理由: 検索の本数を保つため（#37: 検索を絞ると、特定の文に要る公式ページが池から落ちる）、
また #31 の数値の扱い（取り除いて検索する）と揃えるため。破った形のまま検索しない理由: それが逆向きそのもの
（中身を書いたページを集める）だから。

この点検で見つかるのは、生成が content に挙げた語と数値・日付が、そのままの形で問いに入っている場合だけである。
言い換えた中身（「義務づけられた」を「義務化」と書く等）や、content に挙げ忘れた中身は見つからない。それは手順⑥と例示で抑え、
見つかった分は `queryViolations` で数える。

池に入れるのは点検を通った形の検索語だけである。③の候補の順と、段2の上限を当てる順（この主張の検索→記事全体の検索、
各検索の順位。ADR-0016・0018）も、`evidenceTrace.query` も、同じ点検後の検索語で決まる。破った形の検索語は池に入らない。

### 触らないもの

③資料の選び方（ADR-0016・0018。source-pool・source-selection・support-question・JEV の段階判定と上限）、
④JEVへの渡し方（ADR-0014）と JEV まわり、①主張の取り出し（ADR-0017）、信頼度の決め方と表示（ADR-0008・0011）。
検索の本数の上限と並列化（ADR-0015）も変えない。

## ADR-0015 から置き換える部分

- 「指示文は3部構成で、出力形式を固定する」の中身（手順①〜④、ガイドライン、禁止事項、例示、出力の形）→ 上の
  「主張ごとの問いの指示文」。ガイドライン「固有名詞は主張の表記のまま」は「対象は主張の表記のまま」に、禁止事項
  「検査中の数値・日付・金額・割合を入れない」は「主張の中身（値・並べた要素・限定語・結論）を入れない」に広げる。
  例示（改正健康増進法）は、2本目に結論（屋内禁煙）が入っていたので外す。
- 「コードでも2つの規則を守る（`cleanClaimQueries`）」→ 上の「コードでの点検」。黙って取り除く・捨てることをやめ、記録に残す。
- 記事全体の検索語の作り方（ADR-0015 は「6本は残す」とだけ決め、指示文はコードにあった）→ 上の「記事全体の検索語の指示文」。
  本数（6本）と、主張の問いの結果と同じ池に入れることは残す。

残るもの: 全主張について問いを作ること、生成の呼び出しは1回、主張ごと1〜2本、問いを書けなかったときも止まらず主張の文で
検索し直さないこと、並列化。

## Consequences

- 北極星②で、主張の文だけでなく、主張の中身の一部を検索語に入れる形も塞ぐ。検索語は、主張の中身が何であっても
  「対象＋種類＋出所／限定」の同じ形になる。
- 狙い: E2 のように中身が誤った文で、中身を書いた二次ページではなく、対象の定義や提唱元を書いたページが池に入り、信頼度が
  予測どおり低く出る。同じ文の検索語が、回ごとの中身の書き方で揺れることが減る。
- 恐れ: 検索語が広くなり、主張と関係の薄いページが池に増える（③の段1で JEV が対象外と判定すれば落ちるが、
  段2の上限にかかる候補が増えうる）。
- 恐れ: 主張の問いの生成の出力が約2倍になり、実行時間が延びる。
- 恐れ: 生成が content に種類の語（「頭文字」等）を挙げると、その語も問いから取り除かれる。取り除いた語は `removed` に残るので、
  測定のときに読んで判断する。
- 生成が禁止事項をどれだけ破ったかが、本番の応答の `queryViolations` で数えられるようになる。
- 効果は未測定。ADR-0012 の物差しで、記事01を流して前後を比べる: E2（前回 92→96%）が下がるか、仕込んでいない文が下がりすぎないか、
  同じ記事を2回流したときの揺れ幅、`queryViolations` の件数。
- 戻し方: マージ後 `git revert -m 1 <マージのコミット>`。
