# 資料は池の全候補から JEV が選ぶ。出所ごとにまとめ、一次資料かどうかを付け、決まった順で渡す（北極星③を向き直す）

## 向かう方向（ADR-0013 の③）

- 理想: 一次資料（データ表・法令文書・所管官庁・提唱元）を優先し、主要な点は独立した複数の出所で確かめる。
  1件ごとに関連・使えるか・矛盾を判定し、矛盾は捨てずに残す（IFCN、JEV cookbook classifying_rag_passages）。
- 逆向き: 同じ出所の転載を別々の裏付けと数える、矛盾を黙って捨てる、二次要約で済ませる。
- この製品の目的は正誤を決めることではなく、信頼度のブレを管理すること（ADR-0012）。
  資料の選び方も、生成 LLM への指示と同じく「何を・どの順に・どう処理するか」「やってはいけないこと」を固定する。
  同じ入力なら、同じ資料が同じ順で JEV に渡るようにする。

## Context

2026-09-23 時点の③は一部逆向きだった（ADR-0013）。

- 資料の池（ADR-0015 で主張ごとの問いの結果も入るようになった）から、主語・固有名詞の出現回数（1語6回まで）で並べ、
  上位8件に切っていた（#39）。主語を含むページが無い主張だけ、文面の2文字の重なりで8件を選んでいた。
  これは ADR-0007「JEV に聞く前に、こちらの判断で候補を捨てない」に反し、業者サイトが上位に来る型（#39）の原因だった。
- 同じサイトの複数ページも、他サイトの転載も、別々の資料として並べていた（#39 で同じ掲載サイトの2ページが根拠になった）。
- 一次資料かどうかは、ページの並べ替えにだけ使い、JEV には渡していなかった。
- 池のページの並びは、並列に投げた検索・取得の完了順（Map の挿入順）に左右されていた。

JEV公式（2026-09-23 に確認）:

- cookbooks/classifying_rag_passages: 資料ごとに Noul で関連などを判定し、どれを使うかの線はコードで持つ。
  各資料には `source_type`（出所の種類）を属性として付けて渡す。
- models: 1リクエストは 64k トークン（状態＋最長の問いで 32k）。上限は 250,000 トークン/秒・1,200 リクエスト/分。
  料金は入力 100万トークンあたり $0.042。

## Decision

### 選別の手順（この順番で行う）

1. **池の全ページを候補にする。** 並びは、その主張の問いの検索（ADR-0015、1本目は一次の出所を狙う）→ 記事全体の検索語 →
   ほかの主張の問いの検索、の順。各検索の中では検索が返した順位のまま。同じページ（転送で同じ URL になったものも）は最初の1回だけ。
   こちらの点数（主語の出現回数・文面の重なり）で並べ替えも切り捨てもしない。
2. **上限は JEV の入力量だけ。** 1主張あたり、関連の問いに入れる候補は見積もり 120,000 トークン
   （`CANDIDATE_TOKEN_BUDGET` ＝ `RELEVANCE_REQUESTS_PER_CLAIM` 4 × 状態の予算 30,000。日本語で約8万字）まで。
   1の順に、残りに収まるページを入れ、収まらないページは飛ばして数える（長い1ページが後ろの短いページまで締め出さない）。
   飛ばした数は `evidenceTrace.overCap` に入れ、ログにも出す。
3. **出所でまとめる。** 同じドメイン（`www.` と組織内のサブドメインは同じ。`co.jp`・`go.jp`・`lg.jp` 等と都道府県名の `.jp` は
   1段深く見る）は1つの出所。ドメインが違っても、本文がほぼ同一（空白を除いた8文字の並びの見本のうち、短い方の 80% 以上が
   長い方にある。200字未満は比べない）なら転載として同じ出所にする。出所の名前は含むドメインを辞書順に「、」で並べたもの。
4. **一次資料かどうかを付ける。** アドレスだけで見分ける: `go.jp`（官公庁）、`e-gov.go.jp`・官報（法令・官報）、`lg.jp` と
   `pref.`/`city.`/`town.`/`vill.` の `.jp`（地方公共団体）、`ac.jp`・`.edu`・`ac.xx`（学術機関）、`doi.org` と
   パスに DOI を含むもの（学術論文（DOI））、arXiv・J-STAGE（学術論文）、`.gov`・`go.xx`・`.int`・`europa.eu`（政府・国際機関）。
   それ以外は `primary: false`。提唱元・企業の自社サイトはアドレスで見分けられないので付けない（推測で付けない）。
5. **決まった順に並べる。** 一次資料を含む出所 → 出所の名前の辞書順 → 出所の中では一次資料 → URL の辞書順（文字コード順。
   実行環境の言語設定に左右されない）。検索の順位や完了順が変わっても、同じページの組なら同じ順になる。
6. **節に分け、関連を JEV に問う**（ADR-0014 のまま）。全節を問う。
7. **関連の線（0.45）以上の節だけを、5の順のまま残す。** 資料が文と食い違う節も「同じ事柄について述べている」ので残る。
   矛盾をこちらで捨てる処理は無い。
8. **信頼度の問いに、出所ごとにまとめて渡す。** `sources` は
   `[{ origin, sections: [{ title, url, text, primary, primaryKind? }] }]`。
   問いの文面（ADR-0011）は変えない。一次資料を重く見るか、独立した出所がいくつあるかをどう読むかは JEV に委ねる。
   こちらで重みを付けたり、数値を作ったりしない。

吹き出しに並べるページ（関連ありの節を持つページ）も5の順になる。`evidenceTrace.origins` に、根拠になったページの独立した出所の数を出す。

### 禁止事項（これはしない）

- 主語の出現回数・文面の重なりなど、こちらの点数で候補を並べて切る（#22・#39）。
- 同じサイトのページや他サイトの転載を、別々の出所として並べる（別の裏付けとして重ねる）。
- 転載だからといって本文を捨てる。転載で数値だけ変わっていることがあり、捨てると矛盾を黙って捨てることになる。
  転載も節は JEV に渡し、同じ出所の中に並べる。
- 上限で落とした候補を数えずに捨てる。
- 実行ごとに変わる順（並列処理の完了順、Map/Set の挿入順、言語設定に依存する比較）で JEV に渡す。
- 一次資料かどうかで信頼度の数値を加工する。一次資料でないページを捨てる。
- 推測で一次資料と決める（アドレスで分からないものは `primary: false`）。

### 上限の値と理由

- 値: 1主張 120,000 見積もりトークン（関連の問い おおむね4リクエスト分）。
- 理由: これまで1主張に渡していた8ページ（1ページ 5,000〜10,000字）とほぼ同じ量であり、JEV に送る量を増やさない。
  JEV の呼び出しには 429 の再試行がまだ無いので、量を増やすと一度に送る分が 250,000 トークン/秒 を超えて
  主張ごと失敗しうる。上限を上げるのは、再試行（または送る数の制限）を入れてから。
- 見積もりは多めに出る（日本語1字1.5トークン）。実際の入力はおおむね 1主張 8万トークン前後。

## 見積もり（1600字・12〜14主張）

| 項目 | 変更前 | 変更後 |
| --- | --- | --- |
| 1主張に渡す候補 | 主語の出現回数の上位8ページ | 池の全ページを検索の順に、見積もり12万トークンまで（残りは数えて記録） |
| JEV 関連の問い | 1主張 1〜数回（8ページの長さ次第。長いページが続くと最大 20回ほど） | 1主張 おおむね4回（最大5回ほど） |
| JEV 信頼度の問い | 1主張 1回 | 1主張 1回（関連する節が 3万トークンを超えるときだけ数回） |
| JEV 呼び出し合計 | 記録なし（見込み 30〜70回） | 見込み 約 70〜85回（1,200回/分の上限内） |
| JEV 入力 | 記録なし | 最大 約 110万トークン、約 $0.05/記事 |
| 実行時間（JEV の部分） | 関連→信頼度の2段、各段は並列 | 同じ2段。1回の上限 15秒なので最悪 30秒。通常 10〜30秒の見込み |
| 実行時間（全体） | 見込み 55〜75秒（ADR-0015） | 見込み 55〜80秒。最悪でも約 170秒で、上限 300秒（`maxDuration`）に収まる |

出所の判定（8文字の並びの見本の比較）は1主張あたり数十ページ以内で、処理時間は無視できる。未測定。

## Consequences

- 北極星③が「一部逆向き」から「理想の向き」に変わる: こちらの点数で切らない（ADR-0007）、出所の独立性を JEV に見える形で渡す、
  一次資料かどうかを属性で渡す、矛盾する節を捨てない、渡す順を固定する。
- 1件ごとの「使えるか」「矛盾か」を別の問いで判定し、矛盾を別枠に置く段階（cookbook の `contains_answer_evidence`・
  `contradicts_query_premise`）はまだ無い。いまは、関連ありの節を矛盾も含めて同じ `sources` に入れている。
- 同じドメインを1つの出所とみなすので、投稿サイト（note・ブログサービス等）の別々の書き手も1つの出所にまとまる。
- 一次資料の見分けはアドレスだけで行う。提唱元・自社サイトは一次資料でも `primary: false` になる。
- 候補の順が「その主張の問いの検索が先」になったため、主張の問いで見つけた一次資料が、主語を多く含む別のページに押し出される
  恐れ（ADR-0015 の Consequences）は無くなった。代わりに、記事全体の検索で見つけたページは、上限にかかると関連の問いに入らない。
  入らなかった数は `overCap` で見える。
- 効果は未測定。ADR-0012 の物差し（仕込んだ文が低く出るか、同じ記事を複数回流したときの揺れ幅）で、記事01の前後を比べる。
