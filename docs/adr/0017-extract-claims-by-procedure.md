# 主張は、手順・ガイドライン・禁止事項と例示で取り出す。原文の文は写すが、1文まるごとには強制しない（北極星①を向き直す）

## Context

ADR-0013 の北極星①「主張の取り出し」の理想は、1つの事実だけ・それだけで意味が通る（代名詞を実体に置き換える）・
限定語（すべて・必ず・だけ・以上・条件）を残す・原文が真なら主張も真（Claimify, VeriScore, SAFE）。
逆向きは、限定語を落とす、細かく割りすぎる、意見や推測を事実に混ぜる、曖昧な文に解釈を1つ決め打ちする。

2026-09-23 時点の取り出しは「未確認」だった。

- 指示文は3行の方針と出力形式だけで、手順・禁止事項・例示が無い（flow-map の「生成LLMへの指示は3部構成」に反する）。
  言い換え（normalizedText）の作り方は LLM 任せで、限定語の扱い・意見の除き方・曖昧な文の扱いを指示していなかった。
- 同じ指示文が Anthropic と OpenAI に別々に書かれ、細部（factCheckRequired の書き方など）が食い違っていた。
- 生成に temperature は送れない（過去に400）。揺れを抑える手段は指示のあいまいさを減らすことと例示しかない。

原文の文（originalText）の役割: 画面の▶の位置合わせ（先に originalText、だめなら言い換えで照合）と、
JEVに問う文（`claim.original`、ADR-0011・0014）の両方に使われる。

過去の失敗 #45（91e4943）: 取り出しの指示に「originalText は元の1文をまるごと、一字一句そのまま」を足したら、
指摘が11→8件に減り、指示を元に戻した（aa72431）。原因は、同じ文から取った複数の主張の originalText が同じ1文になり、
同じ文の指摘を印から落とす当時の不具合を踏みやすくしたこと。
その不具合は同じ変更で直し、「印に乗らない指摘は場所不明として必ず残す」を不変条件にした（revised-document のテスト）。

## Decision

- **指示文を1か所にまとめる**（`src/lib/providers/llm/claim-extraction.ts` の `CLAIM_EXTRACTION_SYSTEM_PROMPT`）。
  Anthropic と OpenAI は同じ文面を送る。答えの読み取り（`readExtractedClaims`）も共通にする。
- **3部構成で、出力形式を固定する。**
  1. 手順（この順番で、文ごとに、本文の最後まで）:
     ①その文が、資料で確かめられる事実を述べているかを判定する。意見・印象・予測・助言・推奨・仮定は除く。
     断定された事実は、誇張や誤りの疑いがあっても事実として扱う（確かめるのが目的のため）。
     ②述べているなら、事実を述べている語句を originalText に一字一句そのまま写す。
     ③1つの事実ごとに主張文（normalizedText）を作る。代名詞・省略された主語や目的語は、本文中の実体で補う。
     ④限定語・条件・時期・数量・範囲をすべて残す（すべて・必ず・だけ・以上・原則・〜の場合・〜とされる 等）。
     ⑤自己点検: 原文が真なら主張も真か。言い過ぎ・言い足りない・別の事柄なら書き直す。
  2. ガイドライン（こうする）: 本文と同じ言語で書き、訳さない。originalText は本文にそのまま見つかる1続きの語句で、
     **文全体か、その事実を限定語ごと述べている一部**。1つの文から複数の主張を取ってよく、originalText が同じでもよい。
     事実とその条件・例外・単位・時期は1つの主張にまとめる。解釈が割れる文は、本文の言い回しのまま（代名詞だけ補う）にする。
     「〜によると」「〜とされる」などの出所・ぼかしは残す。数値・日付は本文の表記のまま。
  3. 禁止事項（これはしない）: 限定語・条件・時期・数量を落とす・弱める。本文に無い事実・数値・実体を足す、本文を訂正する。
     originalText を言い換える・省略記号で縮める・訳す・複数の文をつなぐ。2つの事実を1つの主張にまとめる、
     単独で意味をなさない断片に割る。意見・予測・助言・仮定を事実の主張にする。曖昧な文の解釈を1つに決める。
     **別の主張が同じ文を使っていることを理由に、主張を省く。**
  - 例示を2つ載せる（検証用の記事10本とは別の題材: 東京スカイツリー、普通自動車免許と初心者マーク）。
    主語の省略の補い、限定語（としては・原則として・以上・必ず・1年間）の保持、意見と助言を除くことを示す。
  - 出力: `{ "claims": [ { "id", "originalText", "normalizedText", "subject", "predicate", "object", "numbers",
    "dates", "entities", "importance", "factCheckRequired" } ] }`。id は出現順に claim-1, claim-2, …。事実が無ければ空配列。
- **#45 と同じ踏み方をしない。**
  - originalText を「1文まるごと」に強制しない。#45 以前から使っていた「文、またはその一部」を保ち、
    その一部に限定語を含めることだけを足す。
  - 主張の数を減らす方向の指示を入れない。同じ文から複数の事実を取ること、同じ originalText を共有することを明示的に許し、
    それを理由に省くことを禁止事項に書く。
  - コードでも主張を落とさない。`readExtractedClaims` は、originalText が重なる主張も、本文に見つからない主張も、そのまま返す。
    印に乗らない指摘は、これまでどおり場所不明として出る（不変条件は変えない）。
- **触らないもの:** ②検索（ADR-0015）、③資料の選び方（ADR-0016）、④JEVへの渡し方（ADR-0014）、信頼度の決め方と表示（ADR-0008・0011）。

## Consequences

- 北極星①が「未確認」から「理想の向き」に変わる（1事実1主張、代名詞の補い、限定語の保持、意見の除外、自己点検）。
  Claimify の「解釈が割れる文は取り出さない」は、主張が減って▶が消える恐れ（#45 の型）があるため採らず、
  本文の言い回しのまま残す形にした。
- 意見・助言・予測の文が主張から外れるため、主張の件数は減りうる。断定された誇張（記事01の①④の型）は事実として残すよう
  手順①に明記したが、効果は未測定。
- 指示文が長くなる（例示込みで約1,000トークン増）。抽出の出力の長さは変わらない見込み。
- 効果は未測定。取り出しを触る変更なので、**必ず本番で前後を比べる**（change-log の規則）。
  物差し: 記事01の主張の件数（前回 12件）、仕込んだ4箇所（E1〜E4）の信頼度と▶、場所不明の件数、
  仕込んでいない文の▶の数。件数が大きく減る、または E1〜E4 のどれかが主張から消えたら悪化として戻す。
- 戻し方: マージ後 `git revert -m 1 <マージのコミット>`。
