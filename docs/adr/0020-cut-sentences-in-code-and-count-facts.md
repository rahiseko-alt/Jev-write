# 文の区切りはコードで決め、LLM は番号付きの文ごとに決まった基準で事実を数える（北極星①の残る揺れを直す。ADR-0017 の一部を置き換える）

## 向かう方向（ADR-0013 の①）

- 理想: 1つの事実だけ・それだけで意味が通る・限定語を残す・原文が真なら主張も真（Claimify、VeriScore、SAFE）。
- 逆向き: 細かく割りすぎる、意見や推測を事実に混ぜる、限定語を落とす、曖昧な文に解釈を1つ決め打ちする。
- この製品の目的は正誤を決めることではなく、信頼度のブレを管理すること（ADR-0012）。同じ入力なら、同じ文が同じ割り方で
  主張になり、同じ文が JEV に問われるようにする。1つの事実ごとに1件、割りすぎない。

## Context

- ①〜④がそろった本番（119c42b）で記事01を2回流すと、主張数が 17件と19件に変わった（change-log の「測定」行）。
  原因は、同じ文を1件の主張にするか2件に割るかが回ごとに変わること。例:
  「口コミの影響力が高まる一方で、広告であることを隠して…「ステルスマーケティング（ステマ）」が問題視されてきました。」は、
  1回目は1件（83%）、2回目は「口コミの影響力が高まっている」59% と「…ステマが問題視されてきた」83% の2件だった。
- JEV に問う文（`claim.original`）は主張の originalText である（ADR-0011・0014・0018）。割り方が変わると問う文が変わり、
  その文に付く信頼度も変わる。
- ADR-0017 の指示は「文ごとに」と書いていたが、文の区切りも、どこまでを1件にするかも LLM に任せていた。
  割る・割らないの基準は「1つの事実ごとに1主張」「単独で意味をなさない断片に割らない」だけで、2つの述語をいつ割るかの線が
  無かった。originalText も「文全体か、その事実を限定語ごと述べている一部」のどちらにするかを LLM が選んでいた。
- 答えの読み取りは返った主張を並べるだけで、記事のどの文が判定されずに終わったかは分からなかった。

## Decision

### 手順（この順番で行う）

1. **文の区切りはコードで決める**（`src/lib/text/sentences.ts` の `splitArticle`）。LLM に文を選ばせたり区切らせたりしない。
   - 行ごとに読む。**見出し行は除く**: 文の終わり方（。！？と、その後の閉じかっこ）をしない行のうち、見出し記号
     （`#`〜`######` と空白、■ □ ◆ ◇ ● ▼ ▽ 【）で始まる行と、後ろに本文が続く最初の60字以内の行（題名）。
     見出しは文脈として LLM に見せるが、判定させない。箇条書き（・など）は見出しにしない。
   - それ以外の行は、かっこ（「」『』（）()【】〔〕［］[]〈〉《》“”‘’）の外にある 。！？ の連なりの後ろで区切る。
     最後の区切りの後ろに残った字も1文。かっこが閉じない行は、かっこを数えずに 。！？ ごとに区切る。
   - 文の前後の空白を除き、空の文は作らない。読む順に s1, s2, … と番号を振る。
2. **LLM は番号付きの各文について、決まった基準（下記）で事実の数を数え、その数だけ主張を作る。** 事実が無い文は、決まった種類
   （opinion・prediction・advice・hypothetical・question・about-the-article・not-a-statement）と理由を付けて対象外にする。
   生成は1回で、全文の文を番号付きで1つの依頼に並べる（見出しは `(heading)` として同じ位置に置く）。
3. **originalText は文そのものから取る。** 事実が1つで除く部分も無い文は、文全体。割った文は、数えた区切り
   （事実と事実、事実と対象外の部分の間）で切った部分: つなぎの語（〜のに対し・〜一方で・〜ため・〜ので・〜し）は前の部分の
   末尾に残し、直後の読点はどちらにも含めず、最後の部分は文末の 。 まで。
4. **コードで確かめる**（`readExtractedClaims`）。
   - 全文の文が「主張あり（件数）」か「対象外（種類と理由）」で返ったか。**欠けた文**（答えが無い、または主張も理由も無い）は
     `missing` として記録（実行の結果 `AnalysisResult.extraction` と、ログの警告）に出す。黙って落とさない。
   - originalText がその文の中にそのままの形で無ければ、文全体に置き換えて注記に残す（JEV に言い換えを問わない。ADR-0011）。
   - 渡していない番号・二重の答え・事実の数と主張の数の食い違い・決まっていない種類は、注記（`extraction.notes`）に残す。
     どの場合も主張は落とさない。
   - 主張の番号（claim-1, claim-2, …）は、コードが読む順に振る。

### 割る・割らない基準（指示文の手順3に固定）

- 2つの述語を2件にするのは、次の両方を満たすときだけ。
  - a. 並列（〜し、〜て、〜で、〜であり、）・対比（〜一方で、〜のに対し、〜が、）・理由と結果（〜ため、〜ので、〜から、）で
    対等につながっている。
  - b. それぞれの部分が、それだけを読んで何についての話か（人・組織・製品・法令・場所などの実体）を言えていて、それぞれ別の
    資料で確かめられる。主語が省かれた部分や、持ち主が別の所にある「高さ」「対象者」「期間」だけを言う部分は、言えていない。
- 1つの述語に付いたものは割らない: 主語・目的語とその修飾（連体修飾節）、条件、限定語（すべて・必ず・だけ・以上・原則として）、
  時・場所・程度、目的、並べた項目、例示、かっこの注記、出所（〜によると・〜とされる）。前の文を指すだけの句
  （これを受け・そのため）は事実に数えず、続く事実に含める。
- 事実と意見・予測・助言がつながった文は、事実だけを数える。
- 迷ったら1件。断定された文が事実かどうか迷ったら、事実として扱う（誇張や誤りの疑いがあっても。ADR-0017 のまま）。
- b を置いた理由: JEV に問うのは originalText である。主語の無い部分（例: 記事01 の「措置命令を受ける可能性があります。」）を
  問うと、JEV は何についての問いかを取れず、段1・段2の「同じ対象か」の判定（ADR-0018）も信頼度も揺れる。
  何についてかを言えない部分には割らず、文全体を問う。
- 記事01の例文は、a（対比「一方で、」）と b（「口コミの影響力」「ステマ」をそれぞれ言えている）を満たすので、基準では2件になる
  （「口コミの影響力が高まる一方で」と「広告であることを…問題視されてきました。」）。

### コードと LLM の役割分担

| 何を | 誰が |
| --- | --- |
| 文の区切り、見出しの除外、文の番号 | コード（決まった規則） |
| 文ごとの事実の数、主張の中身（言い換え・主語など）、対象外の種類と理由 | LLM（基準・例示・出力形式を指示文で固定） |
| 全文の文が返ったかの確認と欠けた文の記録、originalText が原文どおりかの確認、主張の番号 | コード |

### 指示文（`CLAIM_EXTRACTION_SYSTEM_PROMPT`）

- 3部構成（手順・ガイドライン・禁止事項）と固定の出力形式。手順: ①前後の文と見出しを読む ②事実かを判定し、無ければ種類を付けて
  対象外 ③基準で事実を数える ④originalText を取る ⑤1事実1主張を書く（代名詞・省略を補い、限定語を残す）⑥点検（主張の数＝
  数えた数、原文が真なら主張も真）。
- 例示2つ（東京の電波塔、運転免許。検証用の記事10本とは別の題材）。割る例（対比・理由と結果）、割らない例（修飾、主語を省いた
  並列、並べた項目、指示語を補う文）、対象外（意見・記事の説明）、事実と助言がつながった文（事実の部分だけ）を入れた。
- 出力: `{ "sentences": [ { "id": "s1", "facts": 1, "claims": [ { "originalText", "normalizedText", "subject", "predicate",
  "object", "numbers", "dates", "entities", "importance", "factCheckRequired" } ] }, { "id": "s2", "facts": 0,
  "excluded": "opinion", "reason": "…" } ] }`。与えた番号で、文1つにつき1要素、番号順。

### 触らないもの

- ②検索（ADR-0015・0019）、③資料の選び方（ADR-0016・0018）、④JEVへの渡し方（ADR-0014）、信頼度の決め方と表示（ADR-0008・0011）。
- 画面の文の区切りと▶の位置合わせ（revised-document）。

## ADR-0017 から置き換える部分

- 手順①〜③（LLM が本文を読み、文ごとに事実かを判定し、事実を述べている語句を写し、1事実1主張を作る）→ 上の手順1〜3。
  文の区切りはコードが行い、LLM は番号付きの文ごとに、決まった基準で事実を数える。
- ガイドラインの「originalText は…文全体か、その事実を限定語ごと述べている一部」→ 事実1つなら文全体、割った文は数えた区切りで
  切った部分。「1つの文から複数の主張を取ってよく、originalText が同じでもよい」→ いつ複数にするかは上の基準で決まる。
  「別の主張が同じ文を使っていることを理由に、主張を省かない」は禁止事項に残す（コードの置き換えで文全体が重なることはある）。
- 禁止事項の「2つの事実を1つの主張にまとめる、単独で意味をなさない断片に割る」→ 上の割る・割らない基準。
- 出力形式（`{ "claims": [ { "id", … } ] }`、id は LLM が出現順に振る）→ 文ごとの形式。主張の id はコードが振る。
- 読み取りの「originalText が…本文に見つからない主張も、そのまま返す」→ その文の中にそのままの形で無い originalText は文全体に
  置き換え、注記に残す。重なる主張はこれまでどおりそのまま返す。

ADR-0017 のうち変えないもの: 指示文は1か所で Anthropic と OpenAI に同じ文面を送る。3部構成・例示・固定の出力形式。限定語を残す、
意見・予測・助言・仮定を除く、断定された事実は誇張の疑いがあっても事実、曖昧な文の解釈を決めない、代名詞を実体で補う、自己点検。

## #45 を繰り返さない

- #45 は「originalText は元の1文をまるごと」をすべての主張に強制し、同じ文から取った主張が同じ1文になって、当時の画面の
  不具合で印から落ちた（指摘 11→8件）。
- 今回、文全体になるのは事実が1つの文だけで、そのとき主張は1件。割った文の主張は、それぞれ別の部分になる。
- 主張の数は基準で決まり、originalText の書き方からは決まらない。数えた数だけ主張を作るよう指示し、コードは主張を落とさない。
  主張を減らす方向の指示も入れていない（事実か迷ったら事実。同じ文を使うことを理由に主張を省かない）。
- 印に乗らない指摘は場所不明として出す不変条件（revised-document）はそのまま。1つの文から割った主張・文全体に置き換えた主張・
  文を共有する主張が、どれも印に乗るか場所不明で残ることを、取り出しの読み取りから画面の組み立てまで通すテストで固定した。

| 主張の数 | 17〜19（回で揺れる） | 未測定。割るのは a・b を満たす文だけで、迷ったら1件 |

## Consequences

- 北極星①の残る逆向き（割り方が回ごとに変わる、割りすぎ）を向き直す。同じ文はいつも同じ区切り・同じ番号で LLM に渡り、
  割るかどうかは決まった基準で決まる。どの文がどうなったかは `extraction.sentences` に残るので、2回の実行を文ごとに比べられる。
- 効果は未測定。取り出しを触る変更なので、**必ず本番で前後を比べる**（change-log の規則）。物差し: 記事01を2回流し、
  `extraction.sentences` の文ごとの結果（主張の数・対象外）が2回で一致するか、主張数、仕込んだ4箇所（E1〜E4）が主張として残り
  信頼度が予測どおり低いか、場所不明の件数、仕込んでいない文の▶の数、`extraction.missing` と `extraction.notes`。
  E1〜E4 のどれかが主張から消える、または件数が大きく減ったら悪化として戻す。
- 恐れ:
  - 割らない側に寄るため、主張と▶が減りうる（#45 の型）。前後の件数で見る。
  - 見出しに書かれた事実（例: 記事02「■「健康食品」という言葉に法律上の定義はない」）は主張にならない。除いた見出しは
    `extraction.headings` に残る。
  - 主語の省かれた文は、割らずに文全体を JEV に問う。文全体にも主語が無い文（例: E2「Sympathize…の頭文字をとっています。」、
    主語 SIPS は前の文）で JEV に問う文に主語が無いのは、これまでと同じ（④の側の課題）。
  - 事実と助言がつながった文は、事実の部分だけを問う。その部分に主語が無いことがある。
  - 画面の文の区切り（revised-document）は、かっこの中の 。 でも区切る。取り出しはかっこの中では区切らないので、引用の中に 。
    がある文だけ、▶の位置合わせが部分一致になる（合わなければ場所不明として出る。黙っては落ちない）。
  - 主張の数が増えると、JEV の段階判定（ADR-0018）の呼び出しも主張数に比例して増える。
- 戻し方: マージ後 `git revert -m 1 <マージのコミット>`。
