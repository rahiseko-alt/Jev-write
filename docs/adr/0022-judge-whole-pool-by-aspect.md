# 資料は池の全候補を、主張の「側面」について JEV が判定する。決まった順で主張が順番に取り、JEV の公式の上限の速さで締め切りまで判定する（北極星③の向き直し。ADR-0016 の上限を置き換える）

## 向かう方向（ADR-0013 の③）

- 北極星: 信頼度 p% と出た文の p% が渡した資料で裏付けられ、同じ記事を何度流しても値がほぼ揺れない（ADR-0013）。
- ③の理想: 1件ごとに関連を判定する（IFCN、JEV cookbook classifying_rag_passages）。一次資料を優先し、同じ出所の転載は1つにまとめ、
  矛盾する資料は捨てずに残す。判定は JEV が行い、こちらは渡すものを揃えて、返った数値を決まった線で振り分けるだけ（ADR-0007）。
- ③の逆向き: 検索の上位だけを見る。JEV に聞く前にこちらの判断で候補を捨てる。こちらの文字列処理で関連を決める。同じ出所の転載を
  別々の裏付けと数える。矛盾を黙って捨てる。実行ごとに変わる順で渡す。
- この変更の向き: 同じ池なら同じ節が信頼度の問いに渡るようにする（再現性）。JEV に渡る材料が回ごとに入れ替わることを、揺れのもとから外す。

## 経緯

### 今の③（#80・ADR-0016）で起きていること（本番・記事05・29主張、#89 の `result.timings`）

- 1主張の候補（池のページ）は 155〜210件。そのうち 155〜199件が、JEV が関連を判定する前に #80 の上限（1主張 見積もり12万トークン、
  検索の順に先頭から）で落ちていた（`overCap`）。判定にかかったのは 5〜17件だけ。
- 回ごとの揺れの大きいものは、JEV に渡った資料と一緒に動いている。文9は 84/87/40%、文18の後半は 43/62/76%。3回流したときの
  1主張の揺れ幅は中央値2点・平均5.3点・最大47点で、80%の線をまたいだ主張が2件あった。
- 時間: 全体165秒。取り出し106秒、主張ごとの問いの作成 約43秒、検索4秒（63回）、ページの取得20秒（207回）。JEV は関連の問い145回を3秒、
  信頼度の問い76回を2秒で終えた。#89 の締め切りは関連245秒・信頼度270秒で、JEV には約80秒の余裕がある。

### #84（ADR-0018、撤回）が失敗した2つの点

1. 問い「`claim` が述べている対象について述べているか」は、1つの話題の記事では全ページを通した（段1で落ちたのは 0/50）。
   ふるさと納税の記事では、どのページもふるさと納税について述べている。対象ではなく、主張が述べている「側面」を問う必要がある。
2. 3主張で92秒かかり、記事05は300秒を超えて何も返らなかった。#84 のコードから読んだ理由（今の流れは JEV を約50回/秒で回している）:
   - **同時に8本の枠**（`JEV_MAX_CONCURRENT_REQUESTS = 8`）。実行中のすべての JEV の要求が、先着順にこの8本を通った。
     1回0.5〜1秒なら 8〜16回/秒しか出ない。今の流れは関連の145回を一度に送って3秒で終えている（約50回/秒）。
   - **要求の数**。段2は ADR-0014 の節1つにつき1回（`planSectionRequests`）。実際のページは見出しに見える短い行が多く、節はほぼ最小の
     270字付近で切れる（実測: 国税庁・総務省・政府広報オンライン・証券会社・ふるさと納税と通販の仲介サイトの9ページで162節、平均329字、
     1ページ18節）。3主張・50ページの実行でも、段1 50回＋段2 約240〜540回（上限の後に残る約24〜30ページ〔推定〕×10〜18節）＋
     信頼度 24回以下＝約310〜610回。8本の枠・1回0.5〜1秒で、JEV だけで 310÷8×0.5≈20秒〜610÷8×1≈76秒。記事05（約180ページ）では
     段2だけで約1,200〜3,200回になり、JEV の部分で約100〜450秒かかる。
   - **段の間の関所**。段1の全件→段2の全件→信頼度の全件と、それぞれ最も遅い1件を待ってから次へ進んだ。
   - **再試行が枠をふさぐ**。429・5xx は 2・4・8秒待って送り直し、その間も枠を持ったままだった（1件で最大14秒）。
   - 状態は大きくなかった（段1はページの題名と抜粋、段2は1節）。主因は、小さな要求を数千回、8本の枠で順に流したことである。

### JEV 公式（2026-09-24 に確認）

- 上限（https://docs.typesafe.ai/models.md）: jev-1.13 は **250,000トークン/秒・1,200リクエスト/分**。どちらを超えても 429。
  1リクエスト 64k トークン（状態＋全部の問い）、状態＋最長の問いで 32k。「上限は予告なく変わりうる」と明記されている。
  入力100万トークンあたり $0.042（出力は無料）。英語が最も精度が高く、日本語などは同じようにはいかない（同ページ「Language support」）。
- 同時に送る数の公式の上限は書かれていない。cookbook は 4本（https://docs.typesafe.ai/cookbooks/classifying_rag_passages.md
  「公開の窓口には上限があるので小さく」）、8本（https://docs.typesafe.ai/cookbooks/skill_suggestion.md「上限にやさしく」）、
  12本（https://docs.typesafe.ai/cookbooks/rerank_typesafe.md、1,200回を並列）で送っている。
- 1回に複数の問い: `questions` は名前を付けた問いの対応表（https://api.typesafe.ai/openapi.json、`minProperties: 1`）。
  同じ state への問いは1回にまとめる。問いは並列に評価され、問いを足しても返答の時間はほとんど変わらず、増えるのは問いのトークンだけ
  （https://docs.typesafe.ai/primitives.md「Ask multiple questions together」、https://docs.typesafe.ai/patterns/fan-out.md）。
  約54,000字の記事に13問で1回 0.27秒（https://docs.typesafe.ai/cookbooks/parallel_questions.md）。
- 構造化した指示: `instructions` は文字列でもオブジェクトでもよく、データの欄をバッククォートで名指しする（https://docs.typesafe.ai/api.md）。
  1つの state（履歴書）に対し、候補の記録を1問ずつ `instructions` に入れて、同じ1回で何件でも問える
  （https://docs.typesafe.ai/primitives/noul.md「Structured instructions」）。
- Noul（https://docs.typesafe.ai/primitives/noul.md）: 1つの Noul に1つの判断。境界が微妙なときは `criteria` の `true`・`false` で
  「はい／いいえ」を決める。線はコードで持つ。
- classifying_rag_passages（https://docs.typesafe.ai/cookbooks/classifying_rag_passages.md）: 資料1件につき1リクエスト、
  state は「問い＋その1件」。`is_relevant`「この資料は問いの主題を扱っているか」。関連の線 `relevant_min` 0.45 は
  「出発点であって既定値ではない」。同じ「寿命」でも別の種類の寿命を書いた資料は関連 0.08 以下になった（側面の違いを見分けている）。
  資料どうしをまとめて1回にはしない（問いは1組ごと）。
- model-jaggedness（https://docs.typesafe.ai/model-jaggedness/jev-1.13.md）: state に判定と無関係な内容が増えるほど精度が落ちる。
  問いは書いたとおりに読まれる（境界は criteria に書く）。参照の段数を減らす。
- 送り直し: 429 と 529 は間隔を空けて送り直す（https://docs.typesafe.ai/api.md「Handling rate limits」）。SDK の既定は
  408・429・500〜599 を最大2回、500ms から倍（上限5秒）、retry-after は60秒まで守る
  （https://docs.typesafe.ai/sdk/javascript/api/interfaces/RetryPolicy.md）。1回の試行の既定は10秒で、全体の上限は持たない
  （https://docs.typesafe.ai/sdk/javascript/api/interfaces/TypeSafeClientConfig.md）。

## 決めたこと

### 手順（この順番で行う）

1. **候補は池の全ページ。** どの主張にも、池の読めるページのすべてが候補になる（その主張の検索で見つかったかどうかを問わない）。
   その主張のファクトチェック照会の結果は、その主張だけの候補になる。関連の判定の前に、上限でも点数でも1件も落とさない。
   `evidenceTrace.overCap` は残し、JEV の入力上限に1問でも収まらない節があったページの数を入れる（ふつうは0）。
2. **読む節に分ける。** ページを ADR-0014 の分け方（`splitSections`）で節に分け、同じページの中で読む順に、3,122字（ADR-0014 の節の上限）を
   超えない範囲でつなぐ（`readingSections`）。削らず、並べ替えない（つなぎ直すと本文に戻る）。実ページ9件では 162節（平均329字）が
   22節（平均2,421字、1ページ2.4節）になった。関連を問う単位も、信頼度の問いに渡す単位も、この節である。
3. **主張ごとの判定の順を決める**（`judgingOrder`）。①その主張のファクトチェックの結果 ②一次資料（ADR-0016 の `primary`、アドレスで決める）
   ③残り。②と③の中は、その主張の問いの検索→記事全体の検索語→ほかの主張の問いの検索（行った順）、各検索の中は検索が返した順位。
   そのうえで、同じ出所（同じサイト、または本文がほぼ同じ転載。ADR-0016 の `originsOf`）のページを、最初の1件の場所にまとめる。
4. **主張が順番に取る**（`interleave`）。記事の順に、各主張がまだ取られていない次の1ページを取る。取られたページの節は、読む順にすべて並ぶ。
   どの主張も、最初の候補を、どの主張の深い候補よりも先に判定される。
5. **1節につき1回、候補にしている全主張に問う。** state はその節だけ（`{ section: { title, url, text } }`）。問いは主張ごとに1つの Noul
   （下の「問いの文面」）で、主張の文と側面は問いの `instructions` に入れる（公式の構造化した指示）。64k・32k を超えるときだけ、
   同じ節のまま主張を複数の要求に分ける。
6. **JEV の公式の上限の速さで送る**（`JevDispatcher`）。4の順のまま、1秒に始める見積もりトークンが 250,000 を、1分に始める回数が 1,200 を
   超えないように間を空け、同時に走るのは60本まで。1回ごとに #89 の `budget.within`（関連の判定の段）を通す。#89 の仕組みは変えない:
   締め切りまで3秒を切っていたら始めず、締め切りに走っていたものは止め、どちらも「時間切れ」として段ごとに数える。
7. **JEV が「混んでいる」と答えたら送り直す**（`HTTPJEVClient`）。408・429・500〜599 を、retry-after があればその秒数（60秒まで）、
   無ければ 0.5秒・1秒待って最大2回（SDK の既定。SDK の乱数の揺らしは入れない）。待ちも段の締め切りで止まる。1回15秒の時間切れと
   通信の失敗は送り直さない（Anthropic と同じ）。
8. **振り分け（コード）: 関連の答えが線（`RELEVANCE_THRESHOLD` 0.45）以上の節だけが、その主張の材料になる。** 線は1つの設定値で、実行ごとに
   変わらない。食い違う内容の節も「その側面について事実を述べている」ので線を越え、捨てない。
9. **記録。** 主張ごとの `evidenceTrace` に、側面 `aspect`、節の数 `sections`（候補・判定済み・関連あり）、関連の締め切りで判定できなかった節
   `unjudged`（理由「時間切れ」・節の数・ページの URL を判定の予定順に）、JEV が答えなかった節 `unanswered`（理由「JEVの失敗: …」・節の数・
   ページの URL）を出す。`unjudged` と `unanswered` は分ける（時間切れは層0、JEV の失敗は層4。ADR-0006）。ログにも主張ごとに1行出す。
10. **信頼度の問い（ADR-0011 の文面のまま）。** 8で残った節を、ADR-0016 の決まった順（一次資料を含む出所→出所名→出所の中の一次資料→URL、
    ページの中は読む順）で出所ごとにまとめて渡す。1つの要求に収まらなければ ADR-0014 のとおり分けて、答えの最大を取る。主張の順に、
    1主張の要求をまとめて送る（締め切りにかかっても、答えのそろう主張ができるだけ多く残る）。
    - 1節も判定できずに時間切れになった主張は、信頼度を問わない（ADR-0021 のまま）。
    - 1節も判定できず、JEV の失敗があった主張は、失敗として残す（数値を出さない。ADR-0003）。
    - 一部だけ判定できた主張は、判定できた節で問う。時間切れの分は画面に「読みきれなかった資料があります」と出る（ADR-0021 の表示のまま）。

### 問いの文面（1問1判断: この節は主張の側面について事実を述べているか）

側面は、②が主張ごとに書いた「何について」（`about`）と「事実の種類」（`kind`。ADR-0019 の8種類）で名指しする:
`「<about>」の「<kind の語>」`（例:「ワンストップ特例制度 申請書」の「時期・開始年・施行日・期間」）。②が書かなかったとき（時間切れ・生成の失敗）
は、①の主語（`claim.subject`）を「何について」の代わりにする。どちらも無ければ、側面を名指ししない文面にする。

```json
{
  "type": "noul",
  "instructions": {
    "claim": "<記事の原文の文（claim.original）>",
    "aspect": "「ワンストップ特例制度 申請書」の「時期・開始年・施行日・期間」",
    "question": "Does `section` state a fact about `aspect`, the point that `claim` makes?"
  },
  "criteria": {
    "true": "`section` states a fact about `aspect` for the same target as `claim` (a figure, a date, a name, a condition, or how it works), whether it agrees with `claim` or contradicts it.",
    "false": "`section` states nothing about `aspect`: it covers only other points of the same broad subject, or a different target with a similar name, or names `aspect` only as a heading or a link."
  }
}
```

- はい: その節が、主張と同じ相手について、その側面の事実（数値・日付・名前・条件・仕組み）を述べている。主張と一致していても、食い違っていてもよい。
- いいえ: 同じ大きな話題の、別の側面だけを述べている。名前の似た別の相手について述べている。側面の名前が見出しやリンクとして出てくるだけ。
- 主張の文は原文のまま（ADR-0011・0014）。言い換え（normalizedText）は渡さない。
- 文面は英語、データ（主張の文・側面・節）は書かれたまま。英語は JEV の精度が最も高い言語であり（https://docs.typesafe.ai/models.md）、この文面は1回の要求に
  主張の数だけ入り、1記事で約1万6千回（540節×29主張）送られるので、短いほど送る量が減る（#84 の日本語の criteria と比べて、
  見積もりで約半分）。

### ページ単位の先の選別はしない（理由）

ページの題名・URL・検索の抜粋だけで先に選ぶことはしない。抜粋は、そのページが検索に引っかかった部分であって、ページが述べている側面の
全部ではない（国税庁 No.1155 のような解説ページは、控除の仕組み・上限・ワンストップ特例などを1ページで述べる）。抜粋の外に側面がある
ページを落とさない低い線にすれば、ほぼ全部が通って見分けられない（#84: 線0.2で 50/50 が通過）。見分けられる高い線にすれば、JEV に
見せていない部分を理由にページを落とすことになる（ADR-0007）。節を3,122字までつなげば全部の節を判定しても記事05で約540回で済み、
ページ単位の段を足しても、約180回・約170万見積もりトークン（約7秒）が増えるだけで、見分けられない分は減らせない。

### 値と理由

| 何 | 値 | 理由 |
| --- | --- | --- |
| 関連の線 `RELEVANCE_THRESHOLD`（`JEV_RELEVANCE_THRESHOLD`） | 0.45 | 変えない。公式 cookbook の `relevant_min`（出発点）。1つの設定値で、実行ごとに変わらない |
| 読む節の大きさ | 3,122字まで | ADR-0014 の節の上限（citation_check の節の大きさ）。実ページでは ADR-0014 の節が平均329字に寄り、1ページ18節。1節1回・全主張の問いを載せる形では、問いのトークン（29主張で約8,900）が1回ごとにかかるので、節が小さいと回数と量が数倍になり（記事05で約3,300回・約3,000万トークン）、上限の速さでは締め切りに間に合わない |
| 見積もりトークン/秒 | 250,000 | 公式の上限（models）。見積もりは日本語1字1.5トークンで多めに出るので、実際に送る量は上限の約2/3 |
| 回数/分 | 1,200 | 公式の上限（models） |
| 同時に走る数 | 60本 | 公式の回数の上限 1,200回/分＝20回/秒 × 本番の実測の最長の返答 3秒（関連145回を一度に送り、3秒で全部返った）。これより少ないと、上限ではなく枠が速さを決める（#84 は8本） |
| 送り直し | 最大2回、0.5秒・1秒（retry-after は60秒まで） | JEV の SDK の既定（RetryPolicy）。乱数の揺らしは入れない。待ちは段の締め切りで止まる |

測った本番の速さ（関連145回を3秒＝約50回/秒、見積もり約120万トークン/秒）は公式の上限の数倍だが、公式が「予告なく変わる」としている以上、
公式の値で送る。429 が出れば送り直しになり、送り直しは時間の揺れ、時間の揺れは締め切りでの材料の違いを生むからである。
公式の値で送る代わりに、関連の判定は一度に送るより約20秒長くなる（下の見積もり）。

### ガイドライン（こうする）

- 関連は JEV が決める。こちらは、決まった順に、決まった形で問い、返った数値を1つの線で振り分けるだけ。
- 候補の並びは、アドレス（一次資料か）・検索（誰の・どの・何位）・出所だけから決める。同じ池なら同じ順になる。
- 1つの state には1節だけを入れる。ほかに何が見つかったかで、ある節の答えが変わらないようにする。
- 送る速さは公式の上限で決め、同時の枠は上限の速さを妨げない大きさにする。
- 締め切りで判定できなかった節は「時間切れ」、JEV が答えなかった節は「JEVの失敗」として、分けて主張ごとに残す。
- 見積もりは、実測（`result.timings`）と公式の上限から、計算を書いて出す。

### 禁止事項（これはしない）

- JEV の判定の前に、候補を上限・検索の順・こちらの点数で落とす（#80 の12万トークン、#22・#39）。
- 関連を文字列の一致で決める（主語・略語・固有名詞・主張の語が節にあるかで通す／落とす）。コードは JEV の答えと線を比べるだけ。
- ページの抜粋だけで、見分けられない線でページを落とす（#84 の段1）。
- 「同じ対象か」だけを問う（1つの話題の記事では全部が通る）。1つの問いに2つの判断を詰める（「側面について述べ、かつ裏付けているか」など）。
- 食い違う内容の節を関連なしにする・捨てる。
- 実行ごとに変わる順（並列処理の完了順、Map/Set の挿入順、言語設定に依存する比較）や乱数で、送る順・渡す材料を決める。
- 小さな固定の枠（#84 の8本）で JEV を絞る。段の間に、全件を待つ関所を増やす。送り直しの待ちを段の締め切りの外まで延ばす。
- 時間切れの節、JEV が答えなかった節を、関連ありとも関連なしとも決めつけて数える。「関係なし」（`saidNothing`）に数える。黙って捨てる。
- 信頼度の問いの文面・表示・80%の線、①（ADR-0020）、②（ADR-0019）、#89 の時間の仕組み（ADR-0021）を、この変更で変える。

### 触らないもの

- ①主張の取り出し（ADR-0020）、②検索の問い（ADR-0019。`about`・`kind` は②が書いたものを読むだけ）、信頼度の問いの文面（ADR-0011）、
  画面の表示と80%の線（ADR-0011）、#89 の時間の仕組み（ADR-0021。締め切りの値・`budget.within`・時間切れの数え方）。
- #89 のテストのうち、③の要求の形（1主張ごとの関連の要求）に依存していた5件は、新しい形（1節ごとの要求）に合わせた。
  時間切れを記録すること、数値を作らないこと、270秒で返ることの確かめ方は同じ（記事05の規模の偽の実行は、関連の要求が
  25万トークン/秒を超える分だけ1秒遅れて 183→184秒）。②のテストのうち、③の上限の順を確かめていた1件は、判定の順と `overCap` 0 を確かめる形にした。

## ADR-0016・0014・0018 から置き換える部分

- ADR-0016 の手順2（関連判定の前の上限、1主張 見積もり12万トークン、検索の順）→ 廃止。上の手順1。
- ADR-0016 の手順1の並び（その主張の検索→記事全体→残り）→ 上の手順3（一次資料を先に、出所をまとめる）と手順4（主張が順番に取る）。
- ADR-0016 の手順6・ADR-0014 の「1回目: 関連を JEV に問う」（主張ごとに、その主張の全節を1つの state に並べ、「同じ事柄について述べているか」）
  → 上の手順5と問いの文面（1節の state に全主張の側面の問い）。
- ADR-0014 の節の分け方は残し、問う単位・渡す単位は、その節を3,122字までつないだ「読む節」にする（ADR-0014 の節の大きさの範囲内）。
- ADR-0018（撤回済み）の段1・段2・段の間の上限・8本の枠 → 使わない。関連の問いに criteria で境界を書くこと、主張を構造化した指示に入れること、
  1つの state に1節だけを入れることは引き継ぐ。
- 残るもの: ADR-0016 の手順3〜5・7〜8（出所でまとめる・一次資料かを付ける・決まった順・線以上の節を出所ごとに信頼度の問いへ）と禁止事項、
  ADR-0014 の記事全体を渡さないこと・信頼度の問いが収まらないときに分けて最大を取ること。

## 見積もり（記事05、上の実測から）

前提（実測）: 29主張。JEV の前までに約160秒（全体165秒 − JEV 約5秒）。池は 155〜210ページ。1ページの字数は、実ページ9件で平均5,900字、
#80 の上限（12万見積もりトークン）に入った 5〜17ページからは 7,000〜24,000見積もりトークン（4,700〜16,000字）。中央を 180ページ×7,000字とする。

| 項目 | 計算 | 結果 |
| --- | --- | --- |
| 池の字数 | 180 × 7,000 | 約126万字（範囲 155×5,900≈91万 〜 210×7,300≈153万） |
| 関連の問いの回数（＝読む節の数） | 126万 ÷ 2,350字（読む節の平均。実ページ 2,421字） | 約540回（範囲 390〜650回） |
| 関連の問い1回の見積もり | 節 2,350×1.5≈3,500 ＋ 問い 29主張×約307≈8,900 | 約12,400トークン |
| 関連の問いの合計 | 540 × 12,400 | 約670万トークン |
| 関連の問いの時間 | 670万 ÷ 250,000/秒 ＋ 最後の返答 約1秒 | 約28秒（約20回/秒。同時に走るのは 20回/秒×1〜3秒＝20〜60本で、60本の枠に収まる） |
| 信頼度の問い（関連ありが池の r） | 1主張 540×r 節 × 3,500 ÷ 3万 → 回数。29主張分。時間は合計 ÷ 250,000/秒 ＋ 返答 | r=5%: 116回・281万トークン・約13秒 ／ r=10%: 232回・562万・約25秒 ／ r=20%: 464回・1,123万・約50秒 |

| 時刻 | 約160秒＋28秒 → 関連の終わり。＋13〜50秒 → 信頼度の終わり | 関連 約188秒（締め切り245秒まで約57秒）。信頼度 約201〜238秒（締め切り270秒まで32〜69秒）。全体 約205〜245秒 |

JEV の前まで157秒）: 関連540回・見積もり670万トークン・157→185秒。信頼度は r=5%・10%・20% で 116・232・464回、185→198・210・235秒。
どれも締め切りにかからず、全主張に数値が付いた。

## Consequences

- 北極星③の残る逆向きのうち、次が理想の向きに変わる: 候補は JEV の判定の前に1件も落ちない（`overCap`≒0）。関連は「対象」ではなく
  「側面」を、criteria で境界を書いた1判断で JEV が決める。state は1節だけで、ある節の答えが池のほかの中身に左右されない。
  送る順・線は固定で、同じ池なら同じ節が信頼度の問いに渡る。
- 狙い: 記事05を3回流したときの揺れ幅が、今（中央値2・平均5.3・最大47点、線またぎ2件）より縮む。JEV に渡る材料が「検索の上位に
  来たかどうか」で入れ替わらなくなるため。
- 恐れ:
  - JEV の呼び出しが 221回→約660〜1,000回、時間が 約5秒→約40〜80秒、全体が 165秒→約205〜245秒、費用が約2〜3倍になる（上の見積もり）。
    関連ありの節が池の2割を超えると、信頼度の問いが270秒の締め切りに近づく。
  - 関連ありの節が増えると、信頼度の問いが1主張で何回にも分かれ、答えの最大を取る決まり（ADR-0014）で値が上に寄りうる。④の課題として残る。
  - 読む節（最大3,122字）は ADR-0014 の実際の節（平均329字）より大きい。関連ありと判定された節に、側面と関係のない部分も一緒に入る。
  - 側面は②が書く `about`・`kind` で決まる。②の書き方が回ごとに変わると問いも変わり、答えが揺れうる。
  - 側面が狭すぎると、主張を裏付ける節まで「いいえ」になり、信頼度が下がりうる（線0.45は出発点。測って動かす）。
  - 文面を英語にした効果は、この記事では測っていない（公式は英語が最も精度が高いとする）。
  - 公式の上限が下がれば（予告なく変わりうる）、関連の判定が遅くなり、締め切りにかかって「時間切れ」が出うる。
- 測り方: 本番で記事05を3回流し、主張ごとの信頼度の揺れ幅（中央値・平均・最大）、80%の線をまたいだ数、`overCap`、`evidenceTrace.sections`
  （候補・判定済み・関連あり）、`unjudged`・`unanswered`、`result.timings` の関連と信頼度の時間と JEV の回数、`cutShort` を見る。
  見積もり（約660〜1,000回・40〜80秒）と実測を比べる。回数は費用の決まりに従い最小限にする。
- 戻し方: マージ後 `git revert -m 1 <マージのコミット>`。
