# 確信度で三段に振り分ける。JEVは「材料に対する門番」であって知識源ではない

## Context

JEVは判定のたびに確信度を返す。にもかかわらずこの置き場所の実装は、確信度を
「0.5未満なら根拠にしない」という1本の線にしか使っていなかった。JEVが返した数値は
そこで切り捨てられ、利用者に届く結果は「支持／矛盾／確認できず」の3語だけだった。

結果として、根拠となるページが見つからない主張（実数が公表されていない数字など）は
すべて「確認できず」に落ち、見逃しと区別がつかなくなった。

X上の実運用30件を調べたところ、JEVを知識源として使っている例は1件も無く、
全員が「自分で渡した材料に対する門番」として組み込み、確信度で閾値を引いていた
（根拠の採否、出力の採点、振り分け、文脈の圧縮、業務の仕分け、危険操作の門）。
公式文書も、高い＝自動で実行／中＝慎重／低＝人間に回す、と定めている。

## Decision

- **確信度で三段に振り分ける。** 判定ごとに次の扱いを決める。
  - 0.8 以上 … そのまま結果に採用する（矛盾なら矛盾、裏付けなら裏付けとして提示する）。
  - 0.5 以上 0.8 未満 … 「要確認」として提示する。断定しない。
  - 0.5 未満 … 判定として扱わない。人間に回す。
  境界は賭け金で変える。書き換えを伴う判定は上げ、表示だけの判定は下げてよい。
- **JEVに世界の知識を期待しない。** JEVが知っているのは、こちらが渡した状態だけである。
  「この数字は本当か」を材料なしに聞かない。聞けるのは、渡した材料に対する関係だけである。
  したがって、材料を揃えるのはこちら側の責任であり、材料が貧弱なら、JEVは貧弱な材料に対する
  正確な判定を返す。
- **1つの主張について、聞ける問いは1回にまとめて全部聞く。** ページとの関係だけでなく、
  記事内の他の記述との整合性も、同じリクエストの中で問う（ADR-0007 の3番目に従う）。

## Consequences

- 「確認できず」の中身が分かれる。材料が無くて聞けなかったのか、聞いた上で確信が足りなかったのかを、
  利用者が区別できる。
- 閾値は調整対象になる。見逃しが多ければ下げ、誤検知が多ければ上げる。どちらもコードの1か所で済む。
- JEVの判定が外れたと感じたときは、まず渡した材料を見る（ADR-0006 の層の順序）。
