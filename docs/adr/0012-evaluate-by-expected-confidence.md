# 目的は正誤を決めることではない。信頼度が理論上の予測に近く、安定して出るかで評価する

## Context

信頼度を JEV の1つの確率にしたあと（ADR-0011）、日付・数値が食い違う文をコードで判断して▶を付ける変更（#73）を入れた。
信頼度が88%でも▶を付け、吹き出しに「資料では◯（文中は◯）」と出していた。これは信頼度とは別の物差しで、
こちらが正誤を出す形だった。報告も「仕込んだ誤りを何個拾えたか」で数えていた。

利用者の指摘はこうである。

> 正解不正解を決めることが目的ではない。信頼度を必要な箇所にマーキングする事が目的だ。
> 仕込んでいるなら、信頼度は低く出したいんだろ？それが低く出るなら成功、高く出るなら改善の余地ありだが、
> そもそもJevの参照する情報量と情報内容で信頼度は変わるんだから、無理に詰めるな。
> 理論上の予測値と近しい値が高確率で出ることが重要だ

## Decision

- **目的は、確かめる必要のある箇所に信頼度を示して印を付けること。** 正誤を決めない（ADR-0009）。
- **▶は信頼度だけで決める**（ADR-0011: 80%以下）。信頼度とは別の物差し（コードでの値の比較、苦手タグ等）で
  ▶を足さない。#73 は戻した。
- **評価の物差し:** 各文について、渡した資料から理論上予測される信頼度と、実際に出た信頼度を比べる。
  仕込んだ文は低く出るはずで、低く出れば成功、高ければ改善の余地。
- **無理に詰めない。** 信頼度は JEV が参照する資料の量と中身で変わる。特定の文の値を下げるための個別の細工をしない。
- **重要なのは再現性。** 理論上の予測に近い値が、高い確率で安定して出ること。同じ記事・同じ資料で値が大きく揺れる
  （例: 同じ文が84%と68%）こと自体を、直すべき問題として扱う。
- 報告では「何個拾えたか」ではなく、予測と実測の差と、回ごとの揺れ幅を書く。

## Consequences

- 改善の対象は、JEV に渡す材料の質と量（ADR-0007・0008）と、問いの安定性になる。
- 評価には同じ記事を複数回流す必要があり、本番の料金がかかる。回数は必要最小限にする（flow-map の費用の決まり）。
