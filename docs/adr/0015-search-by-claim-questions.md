# 資料は、主張ごとに「確かめるための問い」で探す。1本は一次の出所を狙う（北極星②を向き直す）

## Context

ADR-0013 の北極星②「資料の探し方」の理想は、主張ごとに「確かめるための問い」を作って検索し、一次資料と反証も探すこと。
逆向きは、主張の文をそのまま検索すること、上位の結果だけを見ること。

2026-09-23 時点の実装は逆向きだった。

- 記事全体で検索語6本（`generateDocumentQueries`）を作り、その結果の池から全主張が資料を選ぶ。
- 主張ごとの検索は、池に候補が0件のときだけ1本。書けなければ主張の文（normalizedText）をそのまま検索していた。

過去の経緯: #37 で検索を記事ごとに絞ったら（34→6回）、特定の文に要る公式ページが池から落ち、正しい文が誤検知された。
#31 で、検査中の数値を検索語に入れると、捏造された数値を載せたページは存在しないので何も見つからないと分かった。

## Decision

- **全主張について、生成で「確かめるための問い」を1〜2本作り、それを検索語にする。** 候補0件のときだけではない。
- **生成の呼び出しは1回。** 抽出した全主張を1つの依頼に並べ（ID・言い換え・主語・固有名詞・検査中の数値）、
  主張IDごとの問いを1回で受け取る。主張ごとに呼ばない。
- **指示文は3部構成で、出力形式を固定する**（`CLAIM_QUERY_SYSTEM_PROMPT`）。temperature は送れない（過去に400）ので、
  手順と例示で揺れを抑える。
  1. 手順（この順番で行う）: ①主張の中心となる事柄と主体を特定する ②その事柄を公表・定義している一次の出所
     （提唱元、所管の官公庁、法令・公式ガイドラインの名前、原典の研究・統計、主体自身のサイト）を特定する
     ③一次の出所を狙う問いを1本作る ④主張の限定語・条件（すべて・必ず・だけ・範囲・要件・例外・定義）を確かめる問いを1本作る。
     確かめることが残らない主張は③の1本だけ。
  2. ガイドライン（こうする）: 主張と同じ言語、固有名詞は主張の表記のまま、1本目は必ず一次の出所を狙う、
     代名詞を実体に置き換える、1本8語以内。
  3. 禁止事項（これはしない）: 主張の文（や長い一部）をそのまま検索語にしない、検査中の数値・日付・金額・割合を入れない（#31）、
     推測でドメインや機関名を作らない（知らなければ「所管官庁」「公式サイト」など種類で書く）、1本の問いに2つの事柄を入れない、
     引用符・site:・論理演算子・疑問文を使わない。
  - 例示を1つ載せる（記事01とは無関係の題材: 改正健康増進法）。
  - 出力: `{ "claims": [ { "id": "claim-1", "queries": ["問い1", "問い2"] } ] }`。与えたIDで、主張1件につき1要素。
- **コードでも2つの規則を守る**（`cleanClaimQueries`）。問いに検査中の数値・日付がそのまま入っていたら取り除く。
  主張の文（原文・言い換え）と同じ問いは捨てる。重複を除き、1主張2本まで。
- **記事全体の検索語6本は残す。** 主張ごとの問いの結果と合わせて、同じ資料の池に入れる。
  各主張が池から資料を選ぶ方法（③）と、JEVへの渡し方（④、ADR-0014）は変えない。
- **問いを書けなかったときも止まらない。** その主張は記事全体の検索語で集めた池から選ぶ。主張の文で検索し直すことはしない
  （旧実装の「候補0件なら文で検索」は廃止）。池に主語を含むページが無い主張は、これまでどおり closestFor で池から選ぶ。
- **並列化。** 記事全体の検索語は主張の抽出と同時に作る。記事全体の検索は、主張の問いを作っている間に始める。
  主張の問いの検索は全本を同時に投げ、ページの取得も同時に行う（同じURLは1回だけ読む）。

## 見積もり（1600字・12〜14主張）

| 項目 | 変更前 | 変更後 |
| --- | --- | --- |
| Tavily 検索回数（basic、1回1クレジット） | 6〜8回 | 最大 6＋2×14＝34回（12主張なら30回） |
| Tavily 費用（従量 $0.008/クレジット） | 約 $0.05〜0.06 | 約 $0.24〜0.27 |
| 生成の呼び出し | 抽出1＋記事検索語1（＋候補0件の主張ごとに1） | 抽出1＋記事検索語1（抽出と同時）＋主張の問い1 |
| ページ取得 | 約 40件 | 最大 34×7＝238件（重複を除いて 120〜180件程度の見込み）、全件同時、1件10秒で打ち切り |
| JEV | 文ごとに関連1回＋信頼度1回 | 変わらない（1主張に渡す候補は8件のまま） |
| 実行時間 | 37〜42秒（記事01の実測） | 見込み 55〜75秒。主張の問いの生成（出力 600〜900トークン）で 10〜20秒、検索 1〜3秒、取得 最大10秒が加わる |

最悪の場合（生成が429/529で3回再試行＝待ち計14秒、検索・取得がすべて10秒で打ち切り）でも、抽出 40秒＋問い 35秒＋検索 10秒
＋取得 10秒＋JEV 40秒ほどで、上限300秒（`maxDuration`）の半分以下に収まる見込み。未測定。

## Consequences

- 北極星②が「逆向き」から「理想の向き」に変わる（主張ごとの問い、一次の出所、限定語・条件の確認）。
  「結果を見て問いを作り直す」「最初のサイトから離れて出所を調べる」はまだ行っていない。
- 池が大きくなる。各主張が池から選ぶ方法（主語の出現回数、③）は変えていないので、主張の問いで見つけた一次資料が、
  主語を多く含む別のページに押し出される恐れがある（#39 の型）。起きたら③の側で扱う。
- Tavily の使用量が約4〜5倍になる。従量課金の上限（433 で断られた件、change-log の「環境」行）に早く当たりうる。
- 生成の出力が長くなる。主張が非常に多い記事では、`max_tokens`（16384）には十分余裕がある（14主張で1,000トークン未満）。
- 効果は未測定。ADR-0012 の物差し（仕込んだ文が低く出るか、同じ記事での揺れ幅）で、記事01を流して前後を比べる。
- 戻し方: マージ後 `git revert -m 1 <マージのコミット>`。
