## 2026-09-22 結果画面の作り替え #3〜#7 を完了し main へ取り込み（merge commit e0916ed）

**決めたこと**

- issue #3〜#7 をすべて実装し、PR #8 として main へ取り込んだ。結果画面は「修正版の全文が先、印を押すと詳細が開く」形になった。
- 新しい部品 `src/lib/revised-document` が画面の材料をすべて作る。画面側は表示状態だけを持つ。テストは76件がこの部品の公開関数経由。
- 印は3種類（事実の修正=赤実線＋✎、AI表現=紫波線＋✦、根拠なし=橙点線＋?）。色・記号・線種の3つで区別する。取り消した箇所は種類の色と記号を保ったまま破線＋↩で示す。
- 採用の取り消しは文単位ではなく修正単位。同じ文の別の修正は残る。AI表現の取り消しだけは文全体を戻す（その指摘が文全体を対象にしているため）。
- 採用できるものが無い場合はボタンを出さない（根拠なし／確認済み／位置を特定できない／修正後が元と同じ）。状態ごとに別の文面を出す。
- 1024px 未満は1列＋下からの引き出し、以上は本文＋右パネルの2列。タブはスマホが「原文／修正版」の2つ、広い画面は4つ。広い画面から狭めると修正版に戻る。
- 実機（Playwright、390px と 1280px）で動かして確認する運用を確立した。見た目は自動テストせず、実機で確認する。
- 4巡の2軸点検（Standards / Spec）を行い、見つかった不具合はすべて修正済み。主なものは、印が実データでは常に文全体に広がっていた件、位置を特定できない指摘が無関係な文に印を付け取り消すと別の文が壊れる件、同じ文の片方を取り消すともう片方の修正が消える件、文字数が場所ごとに違う件、スマホで全文が画面外に押し出されていた件。

## 2026-09-22 結果画面の作り替え #3・#4 を実装（PR #8、下書き）

- 文字数表示は原文・修正版とも同じ組み立て方の文字列から数える。以前はタブごとに基準が違い、同じ修正版が3880と3852に見えていた。
