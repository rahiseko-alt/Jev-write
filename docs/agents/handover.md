## 2026-09-22 結果画面を「修正済み全文が先、差分は任意」に作り替える方針を決定（commit 812c5aa）

**決めたこと**

- 結果画面は処理済みの全文を最初に出し、元の段落構造を保つ。コピーボタンは全文画面の上部に常時表示し、「…」メニューからは外す。コピー内容は採用状態を反映した本文のみで、押すとボタンが数秒「コピーしました」に変わる。
- 全文の中で印を付けるのは「事実の修正（語句単位）」「AI表現（文単位）」「要確認（根拠不足）」の3種類のみ。確認済みには付けない。色と記号の両方で見分ける。採用を取り消した箇所は印を残したまま見た目を変える。
- 印を押すと、1024px未満は画面下からの引き出し、1024px以上は既存の右パネルにその Finding の Revision Diff・根拠・採用切り替えを出す。画面の自動スクロールはしない。「関連する指摘」は廃止。
- 表示切替タブは残すが副次的な位置づけ。スマホは「修正版／原文」の2つのみ、左右比較とインライン差分は広い画面だけ。「原文」タブには印を付けない。指摘ゼロ件のときは全文の上に「修正箇所はありませんでした」と添える。
- 「要確認」は採用切り替えを出さず、理由と自分で裏取りを促す案内のみ出す。指摘の見出しは「種類＋対象の語句」で組み立てる。
- 同時に直すもの: 指摘見出しの iPhone 記事向け決め打ち、架空の「〜分前」表示。処理中の進み具合表示は今回やらない（別件）。
- 用語を CONTEXT.md に追加（Revised Document / Finding / Adoption / Revision Diff）。Revision Diff は既存の Delta Check（修正後のハルシネーション検査）とは別物として名前を分けた。
- 決定は docs/adr/0005 に記録。ADR-0002 が記述していた「multi-tab result dashboard」はこれに置き換わる。

**次にやること**

- `/to-spec` を実行し、この方針を仕様として書き出す。
- その後 `/to-tickets` → `/implement` → `/code-review` の順に進める。
- PR #1（左サイドバー削除・入力画面の整理・本方針の記録）は下書きのまま。実装前に取り込むか、実装を同じ枝に重ねるかを決める。

**未解決の問題**

- providers.test.ts の HTTPFetchProvider 判定が失敗したまま（本件以前から存在）。
- 段落を保ったまま Finding を語句単位で位置決めする方法は未設計。修正後の全文と原文の対応付けが要る。
