# 検知の変更記録（消さない）

利用者の命令で作った、消えない記録。引き継ぎメモと違い、**件数で削らない・書き換えない・古い行を消さない。**
直すと別の箇所が悪化することを繰り返したため、変更1件ごとに「何を変えたか」「どう良くなったか」「何が悪くなったか」「戻し方」を残す。

## ゴール（2026-09-23 確定。達成まで寄り道禁止）

本番を人として使い、次のすべてを同時に満たしたら完了とし、検知の改修を止める。吹き出しは確認事項の1つに過ぎない（利用者の指摘）。

動作（1つでも崩れたら不合格）
1. 貼る→実行→結果まで、人の操作だけで迷わず進める。
2. 10本すべてが最後まで止まらずに終わる。失敗・時間切れ・「確認できませんでした」の表示が出ない。
3. 記事の全文が処理され、結果に抜けたブロックが無い。
4. 待ち時間の間、進んでいることが画面で分かる。
5. スマホ幅（390px）と PC 幅の両方で、結果を読んで操作できる。

検知（見直し中。利用者の指摘「正しい、誤った、という概念は存在しない」「数値で示している」による）
6. 表示は「信頼度〇〇%」の1つだけ。信頼度80%以下の文にはすべて▶を付ける（利用者の指定）。
7. 信頼度が何の数値かは、こちらで1つに決めてADRに残す（未決定）。JEVの入口に蓋をしない（ADR-0007）。

中身
8. 吹き出しを読めば、書き手が何を確かめればよいか分かる。
9. 根拠のページが開けて、その文に関係する内容である。

手段は未定（信頼度の定義を決めてから決める）。#52 は経緯に反していたため戻した。

## 規則

- 変更は1つずつ。1つの変更＝1つのPR（1つのマージコミット）にする。複数の直しを混ぜない。
- 取り込んだら、この表の一番下に1行足す。測る前は「効果」を「未測定」と書き、測ったら同じ行を追記で更新する（元の記述は消さず、`→` で続ける）。
- 効果の物差しは「口コミ記事（1844字）の誤り5点のうち何点に▶が付いたか」と「それまで拾えていたものを落としていないか」。件数の増減だけでは書かない。
- 自動の検査が通ることと、人が使って問題ないことは別（利用者の指摘）。本番に実際の記事を通し、▶と吹き出しを人の目で読める形で確かめるまで「直った」と書かない。
- 悪化したら、すぐ戻す: `git revert -m 1 <マージのコミット>` を1つのPRにして取り込む。戻したこともこの表に1行足す。
